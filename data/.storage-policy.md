# Storage Policy

Single source of truth for retention, archival, and cleanup across the ResearchAssistant workspace. Enforced by weekly and monthly cron scripts.

## Retention Tiers

| Path | Tier 1 (active) | Tier 2 (archive) | Tier 3 (summary only) |
|------|----------------|------------------|------------------------|
| `data/logs/learner/runs/*.md` | 0-7 days uncompressed | 7-90 days in `archive/YYYY-MM/runs.tar.gz` | >90 days: deleted if monthly summary exists |
| `data/drafts/ide_session_*.md` | 0-90 days uncompressed | >90 days gzipped in `archive/YYYY/` | N/A |
| `spaces/*/communication/images/` | Indefinite if referenced | N/A | Orphans reported after 60 days (not auto-deleted) |
| `/tmp/*.out` (agent outputs) | Until macOS reboot | N/A | N/A |
| `/tmp/ra-experiments/**` (variance/eval experiment scratch) | Until validated by judge, then deletable; hard cap a few days | N/A | Keep only the synthesis report (COMPARISON/EVAL_SUMMARY) if worth retaining, in-repo; delete the per-agent memos |
| `.kiro/.gpu-agent-done/*.done` | Until claimed by `sentinel-reconcile.sh` (every message) | Moved to `.kiro/.gpu-agent-done/processed/` on claim | Deleted from `processed/` after 14 days |
| `.kiro/.gpu-agent-done/*.running` | While agent runs | Cleared on completion or when reconciler detects a stall | N/A |
| `.kiro/.ingest-pending/` | Status: initialized (≤7d warn, ≤30d delete); committed (30d retain audit); rolled_back (14d retain) | N/A | N/A |
| `data/logs/backend_comparison.jsonl` | Append-only, rotate at 10MB | Rotated files kept indefinitely | N/A |
| `data/logs/status/weekly_*.md` | Indefinite | Small files, no cap needed | N/A |

## Hard Caps (Learner Memory)

Enforced by `scripts/learner-size-check.sh` after every `ra-learner` invocation:

| File | Token cap | Behavior on breach |
|------|-----------|---------------------|
| `data/wiki/shared/learner/orchestrator_patterns.md` | 2000 | Learner must re-consolidate |
| `data/wiki/shared/learner/orchestrator_failures_recent.md` | 1000 | Learner must drop oldest |
| `data/wiki/shared/learner/{agent-name}_patterns.md` | 500 | Learner must re-summarize |

## Image Handling

- Auto-compressed to JPEG quality 85 on ingest if >200KB.
- Filename: `{YYYY-MM-DD}_{short-slug}.{png|jpg}`.
- Referenced from wiki pages via relative paths.
- Orphan detection after 60 days; report only, no auto-delete.

## Steady-State Disk Estimate

| Component | Annual growth | Steady state |
|-----------|--------------|--------------|
| Learner logs (3-tier) | ~60MB |
| Session scratchpads | ~15MB |
| Images (compressed) | ~1GB |
| Wiki pages (markdown) | <50MB |
| Backend comparison log | ~50MB |
| **Total projected** | **~1.2GB/year** |

If steady state exceeds projections by 50%, audit via `bash scripts/ra-storage-audit.sh` and tune compression / orphan policy.

## Subagent / Experiment Scratch (default to /tmp)

Multi-agent fan-outs that generate throwaway artifacts (variance runs, N-way
comparisons, eval sweeps, any "spawn K agents to each produce X") MUST write to
`/tmp/ra-experiments/<run-name>-<YYYYMMDD>/`, never into the repo working tree
(`data/`, `spaces/`). Rationale: these files are not deliverables, they exist
only until the judge/comparator validates them, and they should not clutter the
workspace or risk being mistaken for real outputs.

Lifecycle: generate in /tmp → judge/comparator reads and validates → the small
synthesis report may be copied into the repo if worth keeping → the per-agent
scratch is deleted (macOS clears /tmp on reboot; a hard cap of a few days
applies regardless). A genuine deliverable produced by such a run is promoted
explicitly to its space `output/` dir; everything else stays ephemeral.

## Cron Schedule

See `crontab.example`. Summary:
